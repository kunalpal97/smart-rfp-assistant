# ProposIQ — Frontend

**AI-Powered Proposal Intelligence Platform**

ProposIQ is an enterprise-oriented application designed to streamline the Request for Proposal (RFP) response process. It enables users to manage reference documents, ask questions against organizational knowledge, and generate AI-assisted responses supported by document evidence.

This repository contains the **React frontend** for ProposIQ. It provides a responsive interface for document management, AI-assisted question answering, answer history, and application-level navigation.

## 1. Overview

Preparing RFP responses often involves reviewing large volumes of documentation, locating relevant information, and preparing accurate answers.

ProposIQ simplifies this workflow by providing a centralized interface where users can:

- Upload and manage reference documents.
- Ask natural-language questions about available organizational knowledge.
- Review AI-generated answers with supporting citations.
- Inspect the document evidence used to support responses.
- Access, search, and reuse previously generated answers.
- Use the application through an authenticated, responsive interface.

The frontend handles user interaction and presentation. Document processing, retrieval, AI generation, and persistent storage are handled by the backend and its integrated services.

## 3. Core Features

### Dashboard

The dashboard provides an overview of the application and serves as an entry point to the primary workflows.

It helps users navigate between document management, the AI Assistant, and saved answer history.

### Document Management

The Documents module provides the interface for managing the reference material used by the AI Assistant.

Users can upload documents, review document information, and access available document-management operations.

Document processing and indexing are performed by the backend, which integrates with Azure services.

### AI Assistant

The AI Assistant allows users to submit natural-language questions and review generated responses.

Key capabilities include:

- Question submission through an interactive interface.
- AI-generated responses formatted with Markdown.
- Supporting source citations and evidence excerpts.
- Source document and page references where available.
- Presentation of structured information, including tables.
- Loading, error, and response states.

Answers are generated by the backend's retrieval-augmented generation (RAG) workflow, using indexed document content.

### Answer History

The History module provides access to previously generated answers without requiring regeneration.

Supported capabilities include:

- Search across saved questions and answers.
- Filter answers with or without supporting sources.
- Sort answers by newest or oldest.
- Navigate paginated results.
- View complete saved answers.
- Follow citations to supporting evidence.
- Expand lengthy evidence excerpts.
- Copy saved answers.
- Delete history entries with confirmation.

History records are retrieved from the backend's PostgreSQL storage.

### Authentication and Authorization

ProposIQ integrates with Microsoft Entra ID through MSAL.

The frontend uses the authenticated session to obtain access tokens for protected backend API requests. Backend authorization remains responsible for enforcing user permissions and access boundaries.

### Responsive Interface and Themes

The interface supports desktop and smaller screen layouts, along with light and dark themes.

The selected theme is persisted using the browser's local storage.

### Organization Principles

**Feature-based modules:** Each major application feature groups its pages, components, and API logic where applicable.

**Shared API integration:** Backend communication is centralized through reusable API utilities instead of duplicating request and authentication logic.

**Separation of responsibilities:** UI components handle presentation and interaction, while backend services handle business logic, document retrieval, and AI processing.

## 6. Getting Started

### Prerequisites

Before running the frontend, ensure the following are available:

- Node.js and npm compatible with the project's dependencies.
- Access to the ProposIQ FastAPI backend.
- Microsoft Entra ID application configuration for authentication.
- Required frontend environment variables.

### Installation

Clone the project and navigate to the frontend directory:

```bash
git clone <repository-url>
cd smart-rfp-assistant/frontend-react
```

Install dependencies:

```bash
npm ci
```

For a fresh development environment without a lockfile, use `npm install` instead.

### Environment Configuration

Create a local environment file:

```bash
touch .env.local
```

Configure the frontend with the required Microsoft Entra ID settings and backend API configuration.

Use the **exact environment variable names referenced in the frontend source code**. Vite exposes client-side variables through the `VITE_` prefix.

> **Security:** Frontend environment variables are included in the client application bundle. Never place client secrets, API keys, database credentials, or Azure OpenAI secrets in frontend environment files.

Keep `.env.local` excluded from version control.

### Start the Development Server

```bash
npm run dev
```

By default, Vite serves the application at:

```text
http://localhost:5173
```

The actual port may differ if configured or already occupied.

### Production Build

```bash
npm run build
```

This creates an optimized production build in the `dist/` directory.

### Preview the Production Build

```bash
npm run preview
```

## 7. Authentication and API Communication

ProposIQ uses Microsoft Entra ID for authentication and a protected FastAPI backend for application operations.

A typical authenticated request follows this sequence:

1. The user signs in through Microsoft Entra ID.
2. The frontend obtains an access token through MSAL.
3. The shared API client attaches the token to protected requests.
4. FastAPI validates the token and applies authorization rules.
5. The frontend receives and displays the API response.

Example request header:

```http
Authorization: Bearer <access-token>
```

The frontend handles loading states and API failures, while the backend remains responsible for validating permissions and enforcing tenant and user isolation.

## 8. History API Integration

The History feature communicates with the backend using the following endpoints:

| Method | Endpoint                    | Purpose                                |
| ------ | --------------------------- | -------------------------------------- |
| GET    | `/api/history`              | Retrieve paginated, searchable history |
| GET    | `/api/history/stats`        | Retrieve history statistics            |
| GET    | `/api/history/{history_id}` | Retrieve a saved answer                |
| DELETE | `/api/history/{history_id}` | Delete a saved answer                  |

The history listing supports the following query parameters:

| Parameter       | Description                                 |
| --------------- | ------------------------------------------- |
| `limit`         | Maximum results per page                    |
| `offset`        | Pagination offset                           |
| `search`        | Search question and answer text             |
| `source_filter` | `all`, `with_sources`, or `without_sources` |
| `sort`          | `newest` or `oldest`                        |

The response includes `items`, `total`, `limit`, and `offset`, allowing the frontend to calculate pagination accurately.

## 9. Data and Application State

ProposIQ distinguishes between three main types of frontend state.

**Server state:** API responses such as document lists, saved history, and answer details are managed using TanStack React Query.

**Interface state:** Search input, selected filters, pagination controls, dialogs, and expandable content are managed using React state.

**Persistent browser preferences:** Theme preferences are stored locally using the `proposiq-theme` key.

AI answers and document records are not treated as browser-local persistent storage. Their authoritative data is managed by the backend.

## 10. Security Considerations

The frontend follows these key security principles:

- Authentication uses Microsoft Entra ID.
- Protected backend requests include an access token.
- Sensitive service credentials remain on the backend.
- Authorization and tenant isolation are enforced by backend services.
- Frontend environment files containing local configuration are not committed.
- User-facing API errors are handled without exposing backend secrets.

Frontend access controls improve the user experience but are not a substitute for backend authorization.
